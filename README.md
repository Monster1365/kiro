# 스미싱 예방 앱 (MVP)

의심되는 문자를 붙여 넣으면 스미싱 위험도, 판단 근거, 대응 방법을 쉬운 말로 알려주고, 사용자가 동의한 경우 인증된 보호자에게 알림 SMS를 보내는 안드로이드 앱과 백엔드입니다.

## 구성

```
android/   Kotlin + Jetpack Compose 앱 (MVVM, Room, DataStore, Keystore 암호화)
server/    의존성 없는 Node 20 REST 서버 (분석 / 보호자 인증 / 보호자 알림)
docs/      SMS 자동 수신 검토 문서
```

### 안드로이드 앱 구조 (`android/app/src/main/java/com/smishingguard`)

| 경로 | 역할 |
|---|---|
| `domain/` | 모델(위험 수준, 설정, 이력), 전화번호 검증, 기본 대응 안내 |
| `data/remote/` | `Backend` 인터페이스, `HttpBackend`(실서버), `MockBackend`(외부 서비스 없이 화면 테스트) |
| `data/local/` | Room 이력 DB (`DetectionEntity`) |
| `data/CryptoBox.kt` | Android Keystore AES-GCM. 원문·발신번호·서버 토큰 암호화 |
| `data/SettingsStore.kt` | DataStore 설정 (동의, 보관 기간, 공유 범위, 보호자 상태) |
| `data/AnalysisRepository.kt` | 분석 → 저장 → 사용자 알림 → 보호자 알림 오케스트레이션 |
| `sms/IncomingSmsSource.kt` | 자동 수신 분석 확장 지점. 현재는 "사용 불가" 구현만 연결 |
| `notify/Notifier.kt` | 위험 알림 (잠금 화면에는 원문/URL 미표시) |
| `ui/` | 온보딩, 홈, 문자 분석, 결과/이력, 보호자, 설정 화면 |

### 주요 데이터 흐름

```
[문자 붙여넣기] → 서버 분석 동의 확인(없으면 전송 안 함)
   → POST /api/v1/analyses → 서버가 분석기 호출 + 응답 형식 검증(실패 시 UNKNOWN/FAILED)
   → 앱: 이력 저장(원문 저장 동의 시에만 원문 저장, 암호화) → 사용자 알림(HIGH/CAUTION)
   → 조건 충족 시(HIGH + 보호자 인증 + 자동 알림 켬) 비동기로 POST /api/v1/guardian-alerts
      → 서버가 분석 결과·보호자 인증·동의·공유 범위를 다시 검증하고, 서버에 저장된 번호로만 발송
      → 상태(요청/전송/실패)가 이력에 반영. 보호자 알림 실패는 사용자 경고를 막지 않음
```

## 실행 방법

### 서버

```bash
cd server
npm test                          # 13개 테스트
MOCK_EXPOSE_CODE=true npm start   # http://localhost:8080 (.env 파일은 자동으로 읽지 않으므로 환경 변수로 지정)
```

환경 변수는 `server/.env.example` 참고. AI/SMS 사업자 비밀키(`AI_API_KEY`, `SMS_API_KEY`)는 서버 환경 변수로만 넣고 앱에는 넣지 않습니다. 현재는 규칙 기반 `MockAnalyzer`와 `MockSmsProvider`만 포함되어 실제 AI 호출/SMS 발송은 하지 않습니다.

### 안드로이드 앱

Android Studio(JDK 17)에서 `android/` 폴더를 열고 Sync 후 실행합니다. (Gradle wrapper 파일은 포함되어 있지 않아 Android Studio가 생성합니다.)

- debug 빌드 기본값은 **모의 백엔드**입니다. 서버 없이 전체 화면을 테스트할 수 있습니다.
  - 인증번호는 항상 `123456`
  - 문자에 `[테스트실패]`(네트워크 오류), `[테스트분석불가]`(서버 오류), `[테스트발송실패]`(보호자 알림 실패)를 넣어 오류 상태 확인
- 실서버 연결: `-PuseMock=false -PapiBaseUrl=http://10.0.2.2:8080` (에뮬레이터 기준). release 는 HTTPS 만 허용합니다.

## 명세 반영 요약

- 자동 SMS 수신은 구현하지 않았고 `RECEIVE_SMS` 권한도 선언하지 않았습니다. `IncomingSmsSource` 인터페이스와 `AnalysisRepository.analyzeIncoming`(중복 방지 키 처리 포함)만 준비되어 있고, 설정/홈에는 "사용 불가"와 수동 분석 방법이 안내됩니다.
- RCS/MMS 지원은 표시하지 않습니다.
- 분석 실패·잘못된 응답은 정상 문자로 처리하지 않고 "분석 불가"로 표시하며 재시도를 제공합니다.
- 문자 속 URL은 열지 않고(`Text`는 자동 링크 없음), 본문 속 지시문은 분석기에서 데이터로만 다룹니다.
- 보호자 알림: 서버가 조건을 직접 검증, `idempotency_key`와 (분석, 보호자) 단위로 중복 발송 방지, 최대 3회 재시도, "전송"은 사업자 접수 의미임을 UI에 표기.
- 로그에는 요청 경로와 상태 코드만 남기고 문자 원문/전화번호/URL은 남기지 않습니다.

## 가정 (미확정 사항을 임의 확정하지 않고 표시)

1. 배포 경로, 기본 SMS 앱 전환 여부: 미정 → 자동 수신 미구현.
2. 보호자 인증: 6자리 인증번호(5분 유효, 5회 시도, 60초 재전송 제한). 인증 완료를 수신 동의로 간주. 비용 부담 주체/발송 한도는 미정.
3. AI 제공 방식: 외부 AI 미연동(규칙 기반 모의 분석기). 연동 시 원문 보관·학습 정책 확인 필요. 서버는 원문을 저장하지 않습니다.
4. 서버 저장소는 인메모리입니다. 운영 전 영속 저장소, 사용자 인증 강화(현재는 설치별 토큰), 요청 제한 고도화가 필요합니다.
5. 지원 범위: minSdk 26, SMS 수동 붙여넣기만. 위험도 분류 기준과 오탐/미탐 목표는 5단계(품질 검증)에서 결정.
6. 피드백은 이 기기에만 기록하고 서버로 전송하지 않습니다.
7. 앱 문자열은 현재 코드에 한국어로 직접 들어 있습니다(다국어 리소스 분리는 미적용).

## 검증 상태

- 서버: `npm test` 13개 통과 (분석, 빈 입력, 실패 시 UNKNOWN, 인증번호 제한, 미인증 차단, 공유 범위, 중복 방지, 재시도, 소유권 검사).
- 안드로이드: 이 개발 환경에는 Gradle과 호환 JDK가 없어 **빌드·실행·테스트를 하지 못했습니다.** Android Studio에서 처음 Sync/빌드할 때 컴파일 오류나 버전 조정이 필요할 수 있습니다.
- 미실시: 실기기 접근성(TalkBack/글꼴 확대) 확인, 고령 사용자 사용성 테스트, 오탐/미탐 측정.
